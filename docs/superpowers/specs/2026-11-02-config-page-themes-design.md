# 配置页与主题

**Date**: 2026-11-02

目标：不改代码、不重烧，就能在本地网页上切换屏幕外观、方向和亮度；加一套新外观只需要写一个文件；没收到过设置的设备和以前完全一样。

**硬件状态**：固件已烧进一块板子，但屏幕上的实际效果还没人确认过，见[未验证](#未验证)。

## 架构

```
浏览器 ── HTTP ──→ page/serve.py ── TCP ──┐
                                          ├──→ plugin/scripts/daemon.py ── USB CDC ──→ 固件 handleLine() ──→ THEMES[] + NVS
hook.py / 适配器 ──────────────── TCP ────┘

tools/preview/render.py ── 主机编译真实固件 ──→ page/previews/（雪碧图 + manifest.json）
```

数据流仍然单向。页面和 hook 走同一个 TCP 端口，互不感知；daemon 只转发。页面和 daemon 共用配置文件 `~/.clawd-mood/config.json`，见下文。

| 目录 | 内容 |
|---|---|
| `firmware/clawd_mood/` | `theme.h`（`Theme` 结构、`THEME_TABLE`、主题可读的会话表和绘制函数）、`theme_classic.cpp`、`theme_noir.cpp`、`theme_phosphor.cpp`、`theme_arcade.cpp`、`theme_stage.cpp` |
| `tools/preview/` | `harness.cpp`、`shim/`、`scenes/*.ndjson`、`render.py`、`baseline.txt`、`headline.py`、`headline.cpp` |
| `page/` | `serve.py`、`index.html`、`page.css`、`page.js`、`assets/`、`previews/` |

## 主题

| id | key | 名称 | 风格 |
|---|---|---|---|
| 1 | `classic` | 经典 | 拆分前的外观，也是默认值 |
| 2 | `noir` | 午夜 | 深色地面 + 霓虹，无会话时是月亮星空动画 |
| 3 | `phosphor` | 荧光终端 | 绿色荧光屏上的进程表，`perPage` 6：每行一个会话（小人、标题、`[工作]` 这类状态标签和状态记号），每页 6 行；4 个以内只有一页，行高放大到 51 px、小人放大一级。翻页时整表一帧上滚一行；页码条是底部 20 像素的 `-- 1/2 --`，别的页有紧急会话时那一页的页码闪琥珀或红。单会话是大号小人加三行日志，无会话时逐字打出开机日志 |
| 4 | `arcade` | 街机 | `perPage` 12（`MAX_SESSIONS`）：全部会话排成一个入侵者阵列，不翻页，没有页码条。准星和飞船跟着焦点（`heldUrgent()` 给出的紧急会话优先，否则每个会话轮 2.4 秒），底部字幕显示焦点会话的标题和中文状态。状态靠动作和形状区分，不只靠颜色；子代理是头顶最多 3 架僚机，再多显示 `+N`。无会话时是街机待机画面 |
| 5 | `stage` | 剧场 | `perPage` 1：每页一个主角站在聚光灯下演出自己的状态，灯箱写它的标题，子代理是侧幕的替角（最多 4 个，放不下显示 `+N`），所有会话按到达顺序坐在前排、椅背上有状态灯。`pageMs` 5095，没有页码条（`pagerHeight` 返回 0）；翻页是拉幕，无会话时闭幕「今日休演」 |

主题 3–5 各自只有一个文件，都写成常量初始化（留在闪存），只通过 `theme.h` 的钩子和只读接口画图，没有改共用文件。

**设计来源**：主题 3–5 的视觉来自 Stitch 项目 `17361441364342410358`（clawd-mood 屏幕主题），每个主题一张设计板，和配置页一样只当视觉来源，不用它的代码。稿子里有这些本项目没有或不做的东西，全部去掉：

- 硬件按键和「按键批准 / 拒绝」（KEY-A / KEY-B）：设备没有按键，链路单向。
- 进度条、血条（街机单会话的 BOSS 血条 / 编译进度条）、积分表、PID：没有东西在测进度，也没有分数。荧光终端 working 的行进条和街机 done 的 `+1` 只是装饰，什么都不量。
- DMA 双缓冲 / 脏矩形和预烘焙到闪存的背景：固件每帧整屏画进 `GFXcanvas16` 再推送，主题不碰这一层。
- 荧光终端开机日志里的版本号（固件不知道插件版本）和雷达脉冲；街机单会话的终端日志。
- 剧场 done 的鞠躬：`drawCreature` 的动作是共用的，改成跳起、对勾、金星和彩屑。剧场的等待色比稿子的 `#FFB020` 更亮，和金色边框分得开。

`Theme` 带调色板（按角色分，不借用状态色）、7 个 agent 的造型（`SKIN_COUNT`）、Codex 帽子、图标集，以及可选绘制钩子 `cellBg` / `tile` / `idleScreen` / `overlay`，空钩子走内置绘制；管布局的字段和钩子见下。主题 1、2 的 `perPage` 是 4、`pageMs` 是 0、布局钩子全空，画面和以前一样。

**不分格的布局**（主题 3–5 要用）：

- `perPage`：每页几个会话，1 到 `MAX_SESSIONS`（12）。`pageCount()`、紧急会话的目标页（第 i 个会话在 `i / perPage` 页）、页码条都按它算。12 就是永远一页，不翻页也没有页码条。主题 1、2 是 4。内置网格也能排 5–12 个（6 个以内 3 列，再多 4 列，行数按需），所以只改 `perPage`、不写 `page` 钩子也能用。
- `pageMs`：一页停多久再翻，0 是 `PAGE_ROTATE_MS`（5000）。主机上 5 ms 一轮的循环里，一整轮是 `pageMs + 305` ms，所以 5000 的周期是 5305，和动画周期凑不成闭合的预览。剧场用 5095，一轮 5400 ms，4 页正好 21600 ms（3 × 7200）。
- 钩子，空的就是原来的行为：`page`（画一页：首个会话下标、个数、x 偏移、内容高度，自己画背景）、`transition`（翻页过程，进度 1–`TRANSITION_ONE`（256），6 帧、每帧 50 ms，画整个内容区，代替向左滑）、`pagerHeight`（页码条占几行，空的是多于一页时 `PAGER_H`（4），否则 0；内容高度是 `DISP_H` 减它）、`pager`（画页码条，有会话且高度大于 0 时调用）、`toast`（设置提示）、`enter`（`T` 变化时调用，开机读 NVS 和 `cfg` 都算，只用来重置主题自己的状态，不能画）。
- 每帧的绘制顺序：没有会话时画 `idleScreen`（空的画内置的空屏）；否则翻页中画 `transition`（空的是内置滑动，两边都用 `drawPage`），不翻页时画 `drawPage`；然后是 `overlay`、页码条（`pager` 或内置）、设置提示（`toast` 或内置）。
- 主题读得到的东西全在 `theme.h`：`Session` / `Follower`、`sessions` / `sessionCount`、`currentPage` / `slideTo` / `slideStartMs`、`pageCount` / `slideProgress`、`isUrgent` / `isAlerting` / `heldUrgent`、`labelOf`、`stateColor`、`dimColor`、`skinFor`、`iconFor` / `drawIcon`、`drawCreature`、`drawFollowers`、`labelFont`、`fitLabel` / `drawLabel`（按像素宽度在 UTF-8 边界截断）、`drawLabelCentered`、`drawCell`、`drawPage`。会话表只读。
- 钩子尽量写成 `now` 和会话表的纯函数：预览要闭合，换主题后也不留残影。荧光终端（开机日志从哪一刻开始打）和街机（飞船位置）各存一点状态，都在 `enter` 里重置；剧场不存状态，没有 `enter`。
- 换主题都走 `useTheme()`。每页数量变了，就跳到原来那一屏第一个会话所在的页，正在进行的翻页作废；数量相同（经典 ↔ 午夜）时翻页照常进行，行为和以前一样。主机上测过：12 个会话，24 次切换（19 次在翻页中途），五个主题之间 20 种有序组合都切过，其中 16 种是在翻页中途切的（从街机切出的 4 种做不到，它只有一页）；切换后没有越界的页码，也没有切换前开始的翻页还在进行。之后又用 ASan + UBSan 编译的主机程序，按 1 → 3 → 4 → 5 → 2 → 1 在翻页中途、完成动画和跟班进出时切换（5 和 12 个会话，间隔 1.5 秒和 7 秒），四轮都没有报错，切换后的第一帧都是新主题画的。这些是手动跑的一次性脚本，没有进仓库。

取舍：

- **编译进固件，不从主机上传**：协议单向，没有回包就没法可靠地传大块数据；一套主题还带绘制代码，不只是配色。代价是新主题要重烧一次。
- **元数据放在 `Theme` 里**：`tagline`、`glow`、`minFw` 只给页面用，占几个字节闪存，换来加主题不用改第二份列表。`render.py` 从编译好的固件读它们。`minFw` 目前没有固件版本号与之对照，主题 1–2 写 1，3–5 写 2。
- **id 只增不复用**：`cfg` 和 NVS 都存 id。NVS 里有当前固件不认识的 id（比如降级后）时画主题 1，但保留原值，升级回来还在。

## 设置行

```json
{"cfg":{"theme":2,"rotation":1,"brightness":60}}
```

键都可选，整行小于 319 字节，没有 `state` 字段，走 daemon 现有 TCP 端口。固件在任何会话逻辑之前处理并返回，不创建也不碰会话。

| 键 | 默认 | 不合法时 |
|---|---|---|
| `theme` | 1 | 未知 id 回退主题 1（并按主题 1 保存） |
| `rotation` | 1 | 不是 0–3 的整数就忽略 |
| `brightness` | 100 | 限制到 10–100 |

- **持久化**：`Preferences`（NVS）。`setup` 里首帧前加载；改动后防抖 1.5 秒，只写 `cfg` 改过且和 NVS 不同的键，所以拖滑块只写一次闪存，改了又改回去不写，NVS 里当前固件用不了的值（降级后的主题 id、越界的方向）不会因为改了别的键被覆盖。
- **确认**：有变化时屏幕提示 3 秒，这是单向链路上唯一的确认。没变化不提示。
- **成功时不打串口**：没人读，TX 缓冲满了会卡主循环。
- **背光**：LEDC 5 kHz、8 位驱动 `TFT_BLK`，`ledcAttach` 失败时退回常亮。

## 预览：在主机上编译真实固件

页面上看到的每一帧都是真实固件画的，不是手绘图。`render.py` 用 Arduino 库目录里的 Adafruit GFX、U8g2、ArduinoJson 加 `shim/` 在主机编译 sketch，用虚拟时钟跑场景，经真实的 `handleLine` 送 `cfg` 选主题，把帧写成竖向雪碧图和 `manifest.json`。

选这个方案而不是手绘或画 CSS：外观只有一份来源，改了固件，预览跟着变，不会和设备对不上。

```json
{"themes":[{"id":1,"key":"classic","name":"经典","tagline":"...","min_fw":1,"glow":"#da7756",
  "state_colors":["#949594","#296df6","#18aa41","#ffce00","#ffffff","#e61c18","#41444a"],
  "scenes":{"squad":{"file":"theme-1/squad.png","frames":72,"fps":10,"w":240,"h":240}}}]}
```

- 预览场景是 `squad` / `solo` / `empty`，默认 10 fps，时长取场景文件的 `settle_ms` / `loop_ms`。主题可以在 `Theme.preview`（`PreviewLoop {settleMs, loopMs, fps}`，按 squad / solo / empty 排）里按场景改这三个值，0 表示用场景文件的值或 10 fps；fps 只能是 20 / 10 / 5 / 4 / 2 / 1。焦点轮换、逐页翻的主题要更长的循环。每一帧取那一刻屏幕上的画面，20 fps 能拿到翻页的每一帧（翻页 50 ms 一帧）。
- 现有的设置：主题 1–3 全用场景文件的值。街机 squad `{12000, 9600, 10}`（等过开场 error 会话 10 秒的停留，再走完 4 × 2400 ms 的焦点轮换）、solo `{0, 4800, 10}`、empty `{0, 9600, 10}`（待机画面的游行一轮 9.6 秒）。剧场 squad `{11000, 21600, 20}`：每页一个会话，开场的 error 会把屏幕停在它那页 10 秒（`URGENT_HOLD_MS`），所以要等过去，再翻完 4 页。
- `render.py` 强制检查末帧回到首帧，闭合不了直接报错，所以 `loop_ms` 要是画面上每个动画周期的整数倍，也要是整数帧。squad 场景里各状态的动画合起来是 7200 ms，内置页码条的紧急闪烁是 500 ms。每张图不超过 300 KB（`MAX_SHEET_BYTES`），`page/previews/` 合计不超过 2 MB，超了也报错。一张图的调色板是所有帧颜色的并集：16 色以内是 4 位像素，一帧 28.8 KB，在 deflate 的 32 KB 窗口里，和上一帧相同的帧几乎不占空间；超过 16 色每帧 57.6 KB，够不着上一帧。长循环尽量控制在 16 色以内。现在 15 张图合计 550.1 KB，最大的是剧场 squad，432 帧 179.7 KB。
- `state_colors` 是各主题的 `Palette.state`（RGB565 展开到 8 位，按 Mood 顺序），页面的状态图例直接读它，没有另外手抄的副本。
- `--timing` 报每个主题每帧的主机 CPU 时间（squad、solo、paging-5、paging-12 各跑 3 遍），分普通帧和翻页帧，用来和经典比，当作设备开销的参考，不是设备时间。harness 另有 `--timing FILE` 和 `--trace FILE`（每帧的时间、主题、页、`slideTo`、`slideStartMs`、页数、会话数）。主机 `-O1` 两次运行，单位 µs，均值 / 每轮最大值的中位数（每轮先取四个场景里最慢的一帧，再取三轮的中位数）：

  | 主题 | 普通帧 | 翻页帧 | 和经典比 |
  |---|---|---|---|
  | 经典 | 77.3 / 111.5，77.2 / 111.8 | 90.6 / 101.0，91.4 / 103.7 | 1 |
  | 午夜 | 84.0 / 110.3，83.9 / 113.8 | 100.0 / 115.2，99.0 / 109.0 | 约 1.09 |
  | 荧光终端 | 70.0 / 103.7，69.6 / 101.0 | 68.5 / 89.6，69.1 / 95.0 | 约 0.90 |
  | 街机 | 40.9 / 54.3，40.9 / 52.7 | 没有（只有一页） | 约 0.53 |
  | 剧场 | 51.2 / 62.2，51.4 / 62.2 | 62.8 / 77.0，63.4 / 77.7 | 约 0.66 |

  比值按普通帧均值算。什么都不画的循环每次约 0.11–0.12 µs。
- `baseline.txt` 是主题 1 全部 29 个场景 2957 帧的 hash。拆主题时用它证明外观没变：拆分前后 0 帧不同；之后单独修了翻页时来源标签折行到左边的残影（`canvas.setTextWrap(false)`），29 帧变化，全部在滑动中。
- `--contact` 出总览图，同时报告 RGB565 对比度。主题 2 是 0 条警告；主题 1 有 11 条，都是拆分前就有的颜色，被 baseline 锁住。主题 3 有 14 条、4 有 3 条、5 有 9 条，都是有意的：多数是主题从不这样画的内置配对（比如等待闪烁色上的文字，荧光终端在那里改成黑字），其余是故意做成实心的剪影（CX 的脸和身体同色）和次要文字。
- 它是**主题作者手动跑的工具，不是 CI**，也不改变仓库「没有自动化测试」的约定。它验证的是帧缓冲内容，不是屏幕、背光、NVS 或真机帧时间。

## 配置页

```bash
uv run page/serve.py            # 打开浏览器
uv run page/serve.py --no-open  # 只打印地址
```

**放在 `plugin/` 外**：Codex 对整个插件目录算 hash，放进去的任何文件变动都会让用户重新批准 12 个 hook。`page/`、`tools/` 改动不影响已批准的 hook。

**视觉来自 Stitch 的「舞台中心板」方案，只当视觉来源**：不用它的代码、文案和外链资源。稿子写的 ESP32-S3 和 Wi-Fi 与本项目不符，页面按 ESP32-C3 + USB 写。CSP 不允许字体文件，页面用系统字体；标题 `assets/headline.png` 由 `tools/preview/headline.py` 用固件同款 wqy12 字体生成，整数倍放大。

**页面只说「已发送」，不说「已生效」**。协议单向，设备不回话，页面能看到的只到串口为止：

| 页面文案 | 实际含义 |
|---|---|
| 已发送，请看屏幕确认 | daemon 日志记录了把这行写进串口；如果日志不在预期位置（手动启动的 daemon），等 5 秒后，监听端口的确实是 `scripts/daemon.py`、有设备且日志里没有串口错误也算。5 秒是因为插回后重开串口要约 3.5 秒 |
| 已保存，设备未连接，未发送 | 写入了配置文件，这行没发出去，原因是没有设备、串口打不开或写不进去；下次「应用到屏幕」时补发（`unsent`） |
| 已保存，未发送 | 同上，但断在后台（没装 uv、启动太慢、端口文件指向别的程序等），下面一行写着断在哪 |

TCP 发送成功不算数：daemon 在设备拔掉时仍接受连接并丢弃消息，所以 `serve.py` 要看 daemon 的 `-> line` 日志。旧固件会忽略 `cfg`，页面照样显示已发送，因此有「屏幕没变化，或样式不对？」提示和「重新发送全部设置」按钮（设置没改动时「应用到屏幕」不会发任何东西）。只认主题 1–2 的固件收到主题 3–5 时退回主题 1：原来在主题 1 的屏幕没有任何变化（主题没变，不提示），原来在主题 2 的切到主题 1、提示「主题 经典」，并在 1.5 秒后把主题 1 存进 NVS，覆盖原来的主题 2。页面不知道设备的固件版本，所以只在卡带上标「需新版固件」，在提示里说明这种情况；发出的主题 `min_fw` 较高时，「已发送，请看屏幕确认」下面多一行说明（屏幕没变化或提示「主题 经典」都是这种情况）。

点卡带只改预览，不发串口；按「应用到屏幕」才发，并且只发变化的键。

**安全**：只绑 `127.0.0.1`，随机端口；256 位 token 放在 URL fragment（不进服务器日志），`/api/*` 要带 `X-Clawd-Token`；每个请求检查 Host 和 Origin，防 DNS rebinding；静态文件走白名单；所有响应带 CSP。

**生命周期**：10 分钟没有用户操作退出（状态轮询不算），最长 1 小时。Ctrl-C、SIGTERM、SIGHUP（关掉终端）都走同一条退出路径，会等测试小人的最后一行发完。测试小人的后两行和「保存串口」的重启共用一把锁，不会在重启中途丢掉。

**配置文件**：`~/.clawd-mood/config.json`，用真实用户目录（POSIX 上用 `pwd.getpwuid`，因为 `$HOME` 可能被替换），可用 `CLAWD_MOOD_CONFIG` 覆盖。页面原子写入。

```json
{"serial_port":null,"last_sent":{"theme":1,"rotation":1,"brightness":100},"unsent":[]}
```

只有 `daemon.py`（读 `serial_port`）和页面读它，`hook.py` 和适配器不读。文件缺失或损坏时用默认值并记日志。`last_sent` 是页面最后想要的值，不是设备的真实状态；`unsent` 记发送失败的键，否则失败后再点应用会被当成没有变化。

## daemon 的配套改动（0.3.0）

- **热插拔**：写串口失败时关掉串口但不退出，TCP 继续收。写失败后立刻重新探测和打开一次：没察觉的拔插之后板子往往已经插回，这条消息就不丢。再失败就丢弃消息，之后的消息触发重新探测和打开，每 3 秒最多一次。断开只记一次日志，恢复时带丢弃条数。打开串口约 3.5 秒，期间接受循环停着，新连接排在 TCP backlog（64）里，排得下时 SessionStart 的探活就不会失败，不会拉起第二个 daemon。退出时只删仍写着自己端口的 portfile。已经连着 Espressif 板时，重连只等 Espressif 板，不会落到另一块插着的板子上。启动时没有设备仍然退出。
- **串口选择**：`CLAWD_MOOD_PORT` → 配置文件 `serial_port`（已枚举到才用，否则警告并扫描）→ 扫描（优先 VID `0x303A`，剩多个时警告并取排序后第一个）。
- **连接过滤**：第一个非空白字节不是 `{` 的连接直接丢弃，因为网页也能连这个端口。`recv` 超时 0.3 秒，发呆的客户端不会卡住串行循环。
- **`hooks-codex.json` 的命令加 `|| true`**，和 `hooks.json` 一致。

这些改动让插件版本升到 0.3.0，Codex 用户要重新批准 hook。

## 加一个主题

1. 复制最接近的主题为 `firmware/clawd_mood/theme_<key>.cpp`：只换配色和造型用 `theme_classic.cpp`；保留格子、改格子里的绘制用 `theme_noir.cpp`；自己排版时参考 `theme_phosphor.cpp`（每页多行的列表，自定义翻页和页码条）、`theme_arcade.cpp`（一页放下全部会话）或 `theme_stage.cpp`（一页一个，自定义翻页，不要页码条）。从 `theme_classic.cpp` 复制时删掉 `KNOT_LOGO` 的定义，它全局只有一份。
2. 改全局名和表头：`const Theme THEME_<KEY> = {6, "<key>", "<名称>", "<一句话风格>", 0xRRGGBB, <minFw>, <perPage>, <pageMs>, {调色板}, SKINS, KNOT_LOGO, {图标}, {钩子}, {预览}}`。id 取下一个未用过的数字；名称不超过 8 个汉字，且要在 GB2312 内，设备提示用的是同一款字体。整个主题写成一个常量初始化，它留在闪存；在运行时复制别的主题再改会进内存。
3. 选布局：`perPage` 是每页几个会话（1–12，12 就不翻页），`pageMs` 是一页停多久（0 是 5000 ms）。只用内置网格时钩子全填 `nullptr`；要自己排版就按顺序填 `{cellBg, tile, idleScreen, overlay, page, transition, pagerHeight, pager, toast, enter}` 里需要的，空的走内置。`page` 要自己画背景；`transition` 要画整个内容区；主题自己存的状态在 `enter` 里重置，`enter` 不能画。紧急会话的跳页、10 秒停留、跟班的计时都在 sketch 里，主题只读 `heldUrgent()`、`isAlerting()` 这些结果，不要自己再做一套。
4. 在 `theme.h` 的 `THEME_TABLE` 末尾加 `X(THEME_<KEY>)`。不要动已有项的顺序，`THEMES[0]` 必须是主题 1。
5. 定预览循环：`Theme.preview` 按 squad / solo / empty 各写一组 `{settleMs, loopMs, fps}`，用场景文件的值就写 `{0, 0, 0}`。`loopMs` 要是画面上所有动画周期的公倍数（squad 场景 7200 ms，内置页码条闪烁 500 ms），翻页的主题还要算上一整轮翻页：一页 `pageMs + 305` ms。`perPage` 小于 4 时 squad 场景开场的 error 会话会占住屏幕 10 秒，`settleMs` 要超过它；还要再过停留之后的第一次翻页：翻页会挪动主机 100 ms 一帧的取帧相位，在它之前开始的循环无论 `loopMs` 取多少都闭合不了。稳妥的做法是从停留结束起再等一整轮翻页（`pageMs + 305` ms）。error 会话在第一页时（`perPage` 不小于 3）停留结束不翻页，同样要等过第一次翻页。要看翻页的每一帧用 20 fps。
6. 看效果和对比度：`uv run tools/preview/render.py --contact /tmp/contact.png --theme 6`。它会把三个预览场景都渲染一遍，循环闭合不了就报错退出，不出总览图也不出对比度报告，所以放在定好循环之后。
7. 确认主题 1 没被碰到并生成预览：

   ```bash
   uv run tools/preview/render.py --compare tools/preview/baseline.txt
   uv run tools/preview/render.py
   uv run tools/preview/render.py --check
   ```

   某张图超过 300 KB 或总量超过 2 MB 时报错，缩短循环、降低 fps 或减少颜色；闭合不了时报错，回到第 5 步改 `loopMs` 或 `settleMs`（报错只提 `loopMs`，但起点在翻页之前时改 `loopMs` 没用）。场景文件的时长是所有主题共用的，主题自己的时长写在 `Theme.preview`，不要改场景文件。`uv run tools/preview/render.py --timing` 可以和经典比每帧的主机开销。
8. 页面不用改：卡带、状态图例的颜色和「需新版固件」标记都由 `manifest.json` 生成（`min_fw` 高于最低值的主题带这个标记，并列进「屏幕没变化，或样式不对？」提示）。
9. 编译（默认 + 带 `CLAWD_PROFILE`），烧到板子上看实物，读串口的 `[profile]` 行确认帧时间：

   ```bash
   arduino-cli compile --build-property compiler.cpp.extra_flags=-DCLAWD_PROFILE -b esp32:esp32:esp32c3:CDCOnBoot=cdc,CPUFreq=160,UploadSpeed=921600 firmware/clawd_mood
   ```

主题 3–5 就是按第 1–7 步加的：`THEME_TABLE` 的三项和占位文件先加好，之后每个主题只改自己的文件，没有改共用文件；完成后主题 1 仍是 0 帧不同，主题 2 的预览图逐字节不变。第 9 步只编译过，上板部分没做过。更早的演练是在仓库的临时副本里复制 `theme_noir.cpp` 当主题 3。

## 未验证

**固件已烧进一块板子，但屏幕、方向、调光、NVS 保存和帧时间都还没人确认过。** 硬件行为全部未验证：

- 面板实际输出；`rotation` 在真 ST7789 上的方向；预览的旋转是否和面板一致。
- LEDC 调光；NVS 写入和断电保存。
- 真机帧时间。主题 2 每帧多画扫描线，帧时间没测过。主机上的 profile 数字是 0，因为时钟是虚拟的。
- 主题 3–5 的真机帧时间和新钩子在设备上的开销。上面的 `--timing` 表里它们每帧都比经典便宜，但那是主机 CPU（`-O1`），和 ESP32-C3 的关系没测过。
- 主题 3–5 在 1.54 寸面板上的样子：荧光终端的隔行扫描线、琥珀反显和三档绿色，剧场聚光灯的 Bayer 抖动，街机的霓虹色，远处看不看得清。剧场的抖动直接写帧缓冲（`canvas.getBuffer()`），假设画布旋转是 0；sketch 只转 `tft`，不转画布。
- 配置页带 5 个卡带和新预览的样子：集成主题 3–5 时没在浏览器里打开过。
- 主机帧等于设备帧是假设：主机 `unsigned long` 是 64 位，设备是 32 位，算术只做过人工检查，没测 `millis()` 回绕。
- 真实的 USB 拔插和重新枚举，真实的 VID 读取。上面的 daemon 行为都在 pty 上测，部分场景伪造了串口枚举。
- `ESP_ARDUINO_VERSION_MAJOR < 3` 的 LEDC 分支没编译过，本机只有 core 3.3.10。

设备端能确定的只有编译结果：五个主题齐全时默认构建闪存 618172 字节（47%），全局变量 22192 字节（6%），带 `CLAWD_PROFILE` 是 618950 / 22216，另有堆上 115 KB 的画布。加主题 3–5 之前是 589950 / 22176，三个主题合计多 28222 字节闪存、16 字节全局变量。

**从源码推断，没有测量**：`setSPISpeed(40000000)` 在 `tft.init()` 之前调用，而 `init` 会按 Adafruit 默认的 32 MHz 重新初始化，所以这行看起来不起作用。按 32 MHz 算，推 115200 字节约 28.8 ms，留给滑动帧（50 ms）的绘制时间约 21 ms。带 `CLAWD_PROFILE` 上板后，串口的 `late=` 会显示实际超时帧数。

**其他平台**：Windows 上的 `saved_restart_manual` 分支和脱离进程启动没跑过；Linux 没跑过，没有 `lsof` 时换串口会提示手动重启。只用 headless Chrome 看过页面，页面依赖 `:has` 和 `color-mix`，Firefox、Safari 没试过。

**Codex 的 hash 范围是观察加推断**：本机 Codex 0.166.0 的 `config.toml` 里，本插件 12 个 hook 的 `trusted_content_hash` 完全相同，`trusted_hash` 各不相同，且前者不等于插件缓存里任何单个文件的 sha256。这和「按整个插件目录算」相符，但没有实际改一个文件再看 `/hooks` 的提示。
